# WB Возврат

[![Tests](https://github.com/flokiss42-source/wb-vozvrat/actions/workflows/test.yml/badge.svg)](https://github.com/flokiss42-source/wb-vozvrat/actions/workflows/test.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![Node.js 20+](https://img.shields.io/badge/Node.js-20%2B-43853d.svg)](https://nodejs.org/)

Локальный open-source инструмент для аудита финансовых отчётов и товарного
баланса продавца Wildberries. Помогает находить операции и устойчивые
расхождения, которые стоит проверить перед обращением в поддержку WB.

> Статус: **alpha**. Проект формирует проверяемые сигналы, а не обещает
> компенсацию и не заменяет бухгалтера или юриста.

## Что уже работает

- импорт детализации еженедельного отчёта из CSV;
- загрузка финансовой детализации через официальный WB API;
- поиск крупных удержаний, штрафов, отрицательных выплат и аномальной логистики;
- ежедневные локальные снимки остатков;
- баланс `остаток + приёмка − продажи + возвраты`;
- отдельный учёт продажи и возврата с общим `srid`;
- проверка возвратов продавцу, компенсаций и незавершённых поставок;
- снимки `артикул × склад × время` для оценки ущерба при пожаре, аварии или атаке;
- строгие блокеры, не позволяющие назвать неподтверждённый сигнал потерей;
- локальное хранение: отчёты и токены не отправляются сторонним сервисам.

## Быстрый запуск

Нужен Node.js 20 или новее. Сторонних зависимостей нет.

```powershell
git clone https://github.com/flokiss42-source/wb-vozvrat.git
cd wb-vozvrat
npm.cmd test
npm.cmd run audit -- fixtures/demo.csv
```

HTML-отчёт появится в `reports/`.

## Аудит через WB API

Создайте отдельный read-only токен с категориями `Статистика`, `Аналитика` и
`Поставки`. Не публикуйте токен и не вставляйте его в issue.

```powershell
$env:WB_API_TOKEN = Read-Host 'WB API token'
npm.cmd run audit:api -- 2026-08-01 2026-08-07
npm.cmd run inventory
Remove-Item Env:WB_API_TOKEN
```

Первый запуск `inventory` создаёт базовый снимок. Следующие запуски сравнивают
движение товара за период. Запускайте монитор примерно раз в сутки. Агрегированные
снимки сохраняются в `.wb-data/`, который исключён из Git.

## Как определяется уверенность

| Статус | Условие |
|---|---|
| Наблюдение | Расхождение существует менее 7 дней |
| Вероятная потеря | Расхождение сохраняется от 7 дней |
| Готово к претензии | От 14 дней, доступны все источники, нет активного возврата, незавершённой поставки или непроверенной компенсации |

Статус блокируется, если отсутствует детализация FBW-поставки. Поступления для
финальной проверки берутся из `acceptedQuantity` конкретных поставок, а старый
статистический отчёт используется только как предварительный источник.

## Инциденты на складах

Снимки сохраняют остаток отдельно по каждому складу. Это позволяет для заданного
времени события независимо рассчитать: товарную экспозицию до события, наблюдаемое
снижение после события и уже найденную компенсацию. Снижение не называется
уничтожением без проверки продаж, перемещений, возвратов и документов WB.

Юридическая возможность компенсации рассматривается отдельно от количества
товара: она зависит от действовавшей на дату события оферты, страхования, модели
логистики и официальной квалификации инцидента.

## Ограничения

- WB API отдаёт текущие остатки, но не их прошлую историю. Наблюдение начинается
  с первого локального снимка.
- Внутренние задержки WB могут создавать временные расхождения.
- «Потенциальный риск» — очередь для ручной проверки, не гарантированная выплата.
- XLSX пока необходимо сохранить как CSV UTF-8.
- Проект не отправляет обращения в поддержку автоматически.

## Безопасность

- токен читается только из `WB_API_TOKEN`;
- токен не записывается в отчёты или снимки;
- `.env`, `.wb-data/`, CSV/XLSX и отчёты исключены из Git;
- для работы достаточно read-only категорий API.

Если токен случайно опубликован, немедленно отзовите его в кабинете WB. О
найденных уязвимостях сообщайте согласно [SECURITY.md](SECURITY.md).

## Разработка

```powershell
npm.cmd test
```

Правила участия описаны в [CONTRIBUTING.md](CONTRIBUTING.md). Особенно полезны
обезличенные примеры изменившихся схем отчётов, тесты граничных случаев и ссылки
на актуальную официальную документацию WB API.

## Планы

- карточка доказательств по каждой предполагаемой потере;
- контроль сроков обращения;
- импорт XLSX без предварительной конвертации;
- локальная веб-панель;
- ежедневный безопасный планировщик;
- экспорт черновика обращения в поддержку WB.

Проект не аффилирован с ООО «РВБ» или Wildberries.
